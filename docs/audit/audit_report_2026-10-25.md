## 3. 方法到底是什么（三层，注意第三层已经不是原来的方法）

### 3.1 原始主张：RAPD（README_KD.md、PROGRESS.md）

对每个像素估计"教师的融合证据能被 RGB 学生恢复多少"：

```
r = (cos(g(f_s), f_t) + 1) / 2            ∈ [0,1]
p_u = (1 - ε)·p_t + ε·π,   ε = ε_max·(1 - r)
L_kd = r·KL(p_t‖p_s) + (1-r)·KL(p_u‖p_s) + λ_f·r·(1 - cos(ψ(f_s), f_t))
```

代码：`semseg/kd/probe.py:31-45`（探针）、`semseg/kd/losses.py:118-190`（损失）。

设计意图：r 低（特权证据）→ 目标是"类别先验"，不逼学生复制看不到的东西；r 高 → 纯 KD。

### 3.2 v2 修补（10-23 晚）

加了两个旋钮（`losses.py:141-166`）：分歧门控（学生已同意教师时不回退）、稀有类保护（按先验频率缩小 ε）。最终 v2 采用 `GATE=none, RARE_PROTECT=1.0`——即"分歧门控"被自己否定（方向反了），只留稀有类保护。

### 3.3 现状：真正在跑的是**另一个方法**（TaskAwareKD）

`semseg/kd/task_aware.py` 完全不用 r：

```
w = valid · teacher_correct · class_weight    (class_weight = (1/C / freq_c)^0.5, cap 5)
L_kd = Σ w·KL(p_t‖p_s) / Σ w · τ²
```

P1 的全部 arm 都令 `LAMBDA_FEAT=0`（`configs/kd_mfnet_*.yaml`），也就是说**探针、保守目标、特征项在 P1 里一个都没用**。

**这就是最重要的一条"进度"事实**：仓库叫 RAPD，README 描述 RAPD，但当前唯一有正结果的实验**不是 RAPD**，而是"按类别频率加权的选择性 KD"。这个漂移没有被写进 README_KD.md，也没有被写进任何一处"方法定义"里——一个读者从主页读到的内容和从 `results/REPORT_P1.md` 读到的内容是两套东西。

| ClassBalance | 61.35 | +3.06 |

同一个对比（CE vs Uniform）、同一个 seed：

* batch A：**KD 比 CE 低 0.19**（不显著）；
* batch B：**KD 比 CE 高 1.72**（作者标为显著）。

**同向性都不成立，摆动幅度 1.9 个点，恰好等于整个方法效应量。** 而两批之间的差别只有"数据顺序的 RNG 管线"——一个理论上不该改变结论的实现细节。这只能说明一件事：**MFNet 500-epoch 单次运行的未解释方差约为 1.5–2 mIoU，而所有被比较的效应都在 0.1–3 之间。** 作者在 `ANALYSIS.md §2` 已经用"换机器 +1.70"表述过同一件事，这里是它在同机器同 seed 下的重复。

### 4.7 一个真正稳定、可复现的发现

我把每张图都跑了 teacher/student 逐像素配对，得到夜间 person 像素（506,795 个）的四格表：

| arm | both right | **teacher only** | student only | both wrong |
|---|---|---|---|---|
| CE（batch A，我实测） | 52.98% | **22.53%** | 3.58% | 20.91% |
| CE（batch B，作者报告） | 53.57% | **21.95%** | 3.54% | 20.95% |
| Uniform（batch A，我实测） | 53.41% | **22.10%** | 3.38% | 21.11% |
| RAPD v2（batch A，我实测） | 52.91% | **22.60%** | 3.26% | 21.23% |
| Uniform（batch B） | 53.67% | 21.84% | 3.33% | 21.16% |
| ClassBalance（batch B） | 56.42% | 19.09% | 4.07% | 20.42% |

两次独立的 CE 训练给出 22.53% 与 21.95%，几乎重合；三种 KD 配置（uniform / correctness / classbalance）也都在 19.1–22.6%。**"教师在约 22% 的夜间行人像素上是对的、学生是错的，反向只有 3.3–4.1%"这个事实是稳的**，比率约 6:1。这意味着存在一个巨大的、单向的可转化空间——而所有 KD 配置只把它从 22% 压到 19–22.6%，夜间 person IoU 从 47.6 动到 48.8。

这是本仓库最值得写进论文的东西：**机会是真实的、可测量的，而现有手段几乎没能利用它。**

### 4.8 探针 r 到底有多"没有信息量"

`results/diag_uniform/r_by_class.json` 的逐类 r：

| 类别 | r | ε = 0.5(1−r) | ε = 0.2(1−r) |
|---|---|---|---|
| unlabeled | 0.929 | 0.035 | 0.014 |
| car | 0.897 | 0.051 | 0.021 |
| person | 0.865 | 0.067 | 0.027 |
| bike | 0.881 | 0.060 | 0.024 |
| curve | 0.861 | 0.069 | 0.028 |
| car_stop | 0.841 | 0.080 | 0.032 |
| guardrail | 0.829 | 0.086 | 0.034 |
| color_cone | 0.845 | 0.078 | 0.031 |
| bump | 0.855 | 0.073 | 0.029 |

**r 的类间跨度只有 0.101**（0.829–0.929）。于是：

* "保守目标" `p_u = (1−ε)p_t + επ` 与教师原分布 `p_t` 的最大差别是 **8.6%** 的概率质量（ε_max=0.5），在 ε_max=0.2 时只有 **3.4%**——比常见的 label smoothing（0.1）还小；
* 损失里 `r·KL(p_t) + (1−r)·KL(p_u)` 的权重是 83%–93% 的纯 KD；
* 所以 RAPD 在数值上几乎是 Uniform KD 的恒等变形。**观测到的"RAPD ≈ Uniform（差 0.07）"不是幸运或不幸，是这个定义的必然结果。**

这一点作者没有说透：`ANALYSIS.md §4` 说"r 高，所以方法在行人上早就是纯蒸馏"，这是对的，但没有进一步推出"那么这个方法在任何类别上都不可能偏离 KD 超过 8.6%"。这是把"方法无效"从"调参问题"升级为"定义问题"的关键一步。

### 4.9 class-balance 到底做了什么（我按训练标签精确重算）

`train_label_counts` + `class_balance_weights(beta=0.5, cap=5)`，用 release 里真实的 784 张训练标签算：

| 类别 | 训练像素占比 | 权重 w | KD 梯度质量占比 |
|---|---|---|---|
| unlabeled | 91.865% | 0.348 | **59.95%** |
| car | 4.527% | 1.567 | 13.31% |
| person | 1.380% | 2.837 | 7.35% |
| bike | 0.427% | 5.000（封顶） | 4.00% |
| curve | 0.643% | 4.157 | 5.02% |
| car_stop | 0.545% | 4.513 | 4.62% |
| guardrail | 0.151% | 5.000（封顶） | 1.42% |
| color_cone | 0.175% | 5.000（封顶） | 1.64% |
| bump | 0.286% | 5.000（封顶） | 2.69% |

读法：这个 arm 实际做的事是**把 KD 梯度的 60% 还给背景（原来是 92%），并把 person 的份额从 1.4% 提到 7.4%（5.3 倍）**。这解释了它为什么能让 bump +13.3、car_stop +4.4、guardrail +6.1，而夜间 person 只 +0.9——因为 person 的绝对份额虽然涨了，它本身仍只占 0.9% 的验证像素，且权重被 cap=5 压住了。

**这不是"特权知识迁移"，这是"重加权 + 背景降权"。** 它有效与否的判据只有一个：`p1_cbce`（class-weighted CE，无教师）能不能拿到同样的增益。这个 arm 没跑。

## 5. 有效性判定（逐项）

### 5.1 RAPD 核心机制：无效，且是定义层面的无效

**证据链**：

1. 机制作用幅度上界：ε ≤ 0.086（§4.8），即目标分布与教师分布最多差 8.6% 质量；
2. 同批同协议实测：RAPD v2 59.70 vs CE 59.82 vs Uniform 59.63，**三者两两差 ≤0.19，CI 全部跨 0**（§4.5）；
3. 三个 seed 的 v2：59.01 / 60.08 / 59.65，**sd 0.54 > 与 uniform 的差（0.07）**；
4. 机制唯一可能产生差异的地方（夜间 person，教师 surplus 22%）完全没动：47.62 / 47.85 / 47.45；
5. RAPD 唯一"改善"的是白天 mIoU（59.68 vs CE 59.19，+0.49），**与它的动机（夜间/特权信息）方向相反**；而在它原本声称改善的 guardrail 上，RAPD 42.68 < CE 45.74，**反而低了 3 个点**（作者已撤回该主张）。

**判定：无效。** 不能靠调 ε_max、gate、rare_protect 救回来——因为 r 的动态范围决定了这些旋钮都在 ±8% 的池子里转。作者的 `WORK_SUMMARY.md §10` 也明确写了"不建议继续调这些超参"，这个判断是对的。

### 5.2 保守回退（conservative_only）：无证据

* 唯一一次运行（旧机器、seed 3407）：best 61.01（全表最高）但 **last-10 58.57（全表倒数）**，best−last10 = 2.44（全表最大）——典型的选点偏差；
* 它要证明的东西是"降低幻觉/过自信"，而 **ECE 与幻觉率从未跑通**（`WORK_SUMMARY.md §9.3` 自述 `analyze.py` 的 ECE 分支因 loader 返回 list 与 `model.forward` 不匹配而失败）；
* 也就是说：这个模块的**核心指标是空的**，只有 mIoU 这一个与它无关的指标。

**判定：无证据支持，且证据链断了（D 级）。** 若要救，先补 ECE / 幻觉率，而不是再跑 mIoU。

### 5.3 探针 r 作为"可恢复性"的度量：构念（construct）不成立

一个度量要能当权重用，至少需要：(a) 有区分度；(b) 与关心的结局相关；(c) 经过校准。

* (a) 失败：类间跨度 0.101（§4.8）；
* (b) 失败：person 的 r（0.865）在 9 个类里排**第 4**（unlabeled 0.929 > car 0.898 > bike 0.881 > **person 0.865**），而 person 恰恰是唯一"教师显著更强、学生完全学不到"的类。若 r 真度量"可恢复性"，这里应该最低。顺带指出：`results/ANALYSIS.md §4` 说 person 是"全表第二可恢复"是**数错了**（按 r 排序是第 4），这不影响它的结论，但说明这类手工描述没有经过脚本校验；
* (c) 失败：探针无 held-out、无校准、无 AUC 报告；它本身是被 MSE 优化出来的，训练目标就是"让余弦尽量高"，所以 0.85 这个数字是**拟合结果**，不是测量结果；
* 更进一步：特征项 λ_feat>0 时，`proj` 既被 MSE 训练，又被 `1−cos(proj(f_s), f_t)` 训练（`tools/train_kd.py:316`），而 r 正是 `proj` 的输出——**被测量的量同时被蒸馏目标优化**，这在 v1/v2 里是真实的自我强化回路。

**判定：不能作为"可恢复性"的证据。** 作者自己在 `WORK_SUMMARY.md §7.7` 已经走到门口（"r 高并不矛盾"），但没有把它上升为"这个度量本身不成立"，而是归因于"信息不可迁移"。这两件事需要分开：**信息不可迁移是真的；r 测不出这件事也是真的。**

### 5.4 "热成像承载夜间行人证据"：成立，是本仓库最硬的资产

* 正常热成像：教师夜间 person IoU **65.74**（我实测 65.737）；
* batch 内 roll 打乱对应关系：**16.77**（−49）；
* 置零：0.69，但整体崩塌到 mIoU 1.4，属分布外，不能当对照（作者已正确指出这个坑）；
* 学生（纯 RGB）：47.62，**高于被打乱的教师（16.77）**——说明学生的 47 点来自 RGB 本身，教师多出的 18 点完全来自热成像。

**判定：成立、可复现、可证伪。** 这是可以直接写进论文的实验，也是审稿人会认的那种"机制性证据"。

**但要注意它的推论边界**：这个实验证明的是"教师的能力依赖热成像"，**不直接证明"软标签无法迁移"**。后者是另一个命题，需要"给了足够梯度仍然学不到"的证据。仓库用"4 种 KD 配置都停在 46–48"来支持它——这个证据是相关的，但 P1 的 classbalance 把夜间 person 抬到 48.81（CE 47.91，+0.9；教师缺口 17.8），说明"完全学不到"是过强的表述；准确的说法是"在已有配置下只转化了缺口的约 5%"。

### 5.5 P1 的 task-aware / class-balance：有信号，但当前不可归因

**支持它的**：

* 三个 KD 臂在**同一批内**都高于 CE（+1.7/+1.9/+3.1 观测差），bootstrap CI 不含 0；
* 增益集中在长尾类（bump +13.4、car_stop +4.4、curve +1.6、guardrail +6.1），符合"重加权长尾"的机制解释；
* 这个 arm 的配置是干净的：CE 项未加权（`configs/kd_mfnet_classbalance.yaml:29-32` 的 `CLASS_BALANCE.ENABLE: false`），只有 KD 项被加权，隔离做得对。

**否定它的（三条，按严重度）**：

1. **缺决定性对照**：`p1_cbce`（只有类别加权 CE、没有教师）没跑。若它也到 61 附近，那么"特权蒸馏"这个卖点归零，剩下的只是 loss reweighting——一个 2016 年就有的技巧。作者自己在 `docs/PROTOCOL_P1.md` 里写了这个对照的目的（"so foreground reweighting cannot be mistaken for privileged transfer"），却没跑完。
2. **单 seed + 参照点偏低**：n=1/arm；参照 CE 比仓库自己的 CE 低 1.53（§4.4）；换成自有 CE 后增益 1.53，换成 best 后 −0.37。
3. **与动机错位**：论文的动机是"夜间行人/特权证据"，而这个方法改善的是 bump/car_stop/guardrail 这类样本极少的类，夜间 person 只 +0.9（缺口 18）。**它没有回答论文提出的问题。**

**判定：有统计信号，但归因未完成、效应量被高估、且不解决动机问题。** 现在把它写成"我们的方法提升 3 个点"会被审稿人一击即中（单 seed、缺对照、参照点异常）。

### 5.6 评测协议：质量高于同类工作，但有三个洞

**做得好的**（这部分应该保留，是可复用的资产）：

* 单一评测入口，禁止 TTA、禁止多尺度，per-image 混淆矩阵落盘，可复算 bootstrap；
* 主表用固定第 500 轮（不做模型选择），best 单列为"乐观值"；
* 同时报 official（含 unlabeled）与 foreground 两个口径，事后不可挑选；
* 教师/学生逐像素四格表——这是本仓库最有诊断价值的表；
* 明确的"已知局限"段落。

**三个洞**：

1. **评测集 = 选择集**：392 张既是验证又是测试，`best` 系统性虚高 1.10（我复算一致）。作者知道并处理了（用 last），但**没有任何真正的 held-out 测试集**，因此全部数字只能是"验证集估计"。
2. **CI 只含评测噪声**：image-level bootstrap 估的是"换一批 392 张图会怎样"，估不到"换一个 seed 会怎样"。而后者实测 1.5–2.0（§4.5）。把 `*`（CI 不含 0）当作"方法有效"的证据是**系统性误导**——作者在 `PROTOCOL_P1.md` 末尾承认了，但 `REPORT_P1.md` 的表格没有任何提示。
3. **主证据未入库**：见 §1.3。协议再好，产物不在，就等于没有。

### 5.7 直接回答："RAPD 是不是没有效果？"

**是，但要把"没有效果"限定在三层，否则会推出过头的结论。**

| 层面 | 判定 | 关键证据 | 确定性 |
|---|---|---|---|
| 精度（能不能涨点） | **无效** | 同批同协议 CE 59.82 / RAPD v2 59.70 / Uniform 59.63，Δ 全跨 0；v2 三 seed sd 0.54 > 与 uniform 的差 0.07；夜间 person 47.6/47.9/47.5 对教师 65.74 | 高（我实测） |
| 机制（是不是"还没调好"） | **结构性空转** | r∈[0.829,0.929] ⇒ ε=ε_max(1−r) ≤0.086；`p_u` 与 `p_t` 最多差 8.6% 概率质量，比 label smoothing 还小；KL 权重 83–93% 是纯 KD | 高（由定义直接推出） |
| 度量（r 可不可信） | **构念不成立** | 无动态范围、无校准、无 held-out、无 AUC；person 的 r（0.865）排第 4，恰是最该低的类 | 中高（用仓库 r 数据算） |

必须同时说的三句限定：

1. **被证伪的是"这一版实现"，不是"可恢复性感知蒸馏"这条路线。** 核心度量 r 从未被证明有判别力，所以"换一个有校准、有区分度的可恢复性分数后是否有效"——**没有实验回答过**。
2. **"软标签迁移不了"说过头了。** 数据支持的是"在已有配置下最多转化缺口的约 5%"（夜间 person 47.91→48.81，缺口 17.8），不是"原则上做不到"。要证伪后者，得换被传递的量（特征级/区域级监督）。
3. **"热成像承载夜间行人证据"不受影响。** 打乱热成像后教师夜间 person 65.74→16.77，这条成立，且与 RAPD 无效并不矛盾——它恰恰解释了为什么软标签不够。

一句话：**作为涨点方法可以判死；作为分析框架，它死在自己的度量上，而不是死在"特权信息不可蒸馏"这个命题上。**

| 3 | `semseg/kd/losses.py:96-108` | 类别先验 π 用**每批标签**的 EMA 更新，且包含 92% 的 unlabeled 类；`p_u` 回退方向因此主要指向"背景"——语义上不太对（想要的是"不要过自信"，不是"更像背景"） |
| 4 | `semseg/kd/task_aware.py:89-90,97` | KD 用 `Σw·KL/Σw` 归一化：好处是尺度不随选择比例漂移；副作用是**每批的类别组成会改变总梯度**（小 batch=8，一个 batch 里可能一个 person 都没有），训练信号噪声大 |
| 5 | `configs/*.yaml` 全部 `TRAIN.DDP: true` | 单卡跑法下靠 `dist.is_initialized()` 兜底，能跑，但配置与实际不符，容易误判 batch 语义 |
| 6 | `tools/train_kd.py:281` | `use_rec = True if kd_mode == "task_aware" else epoch >= warmup`：task-aware 从第 0 轮就生效，而它依赖"教师正确性"——教师是冻结的，所以合理；但这意味着 P1 与 P0 的"预热期"不同，跨批比较又多一个差异 |

### 7.1 效应量 vs 噪声（把已知数字放在一张表里）

| 量 | 数值 | 来源 |
|---|---|---|
| 同一 arm 跨机器（同 seed） | +1.70 | `ANALYSIS.md` |
| 同一 arm 跨代码版本（同 seed，CE） | **1.53** | §4.4（我算） |

| 评测集抽样噪声（bootstrap CI 半宽） | ±0.9 ~ ±1.5 | 我实测 |
| 被声称的方法效应 | +0.07（RAPD vs uniform）~ +3.06（ClassBalance vs CE） | §4.5 |

**结论**：方法效应的下界（0.07）比噪声小一个数量级；上界（3.06）也只有噪声的 2 倍，且参照点可疑。用作者自己的功效表反推：

| σ \ Δ | 0.5 | 1.0 | 1.5 | 2.0 | 3.0 |
|---|---|---|---|---|---|
| 0.54 | 19 | 5 | 3 | 2 | **2** |
| 1.00 | 63 | 16 | 7 | 4 | **3** |

要在 σ≈1.0 下把 +3 做成 α=0.05、power=0.8 的结论，需要 **3 个 seed/arm**。也就是 **CE + ClassBalance + cbce 三个 arm × 3 seed = 9 次运行 ≈ 27 GPU·小时 ≈ 2 卡 14 小时**。这个成本是完全可承受的，而它至今没做。

## 8. 论文层面：现在能写什么、不能写什么

**距 CVPR 2027 截稿（项目自述 2026-11-17）还有 23 天。**

### 可以写（证据充分）

1. **"特征可预测性 ≠ 任务证据可迁移"** 的机制性负结果：r_person=0.865（夜间 0.855）而任何 KD 变体都无法移动夜间 person（46–48 vs 教师 65.7）。
2. **反事实热成像实验**（65.74 → 16.77）证明该能力由模态承载。
3. **聚合 mIoU 掩盖条件性差距**：教师 best 61.28 反而**低于**学生的 best 61.72（−0.44），但夜间 person 高 18 个点。这是一个对 MFNet 类基准的通用批评，方法学上有价值。
4. **像素级配对表**作为诊断工具（22% teacher-only vs 3.5% student-only，两次独立 CE 都复现）。

### 不能写（会被打回）

1. "RAPD 提升 mIoU" —— 同批同协议 −0.12。
2. "RAPD 改善 guardrail" —— 同批实测 42.68 vs CE 45.74，是**变差**。
3. "保守回退降低幻觉" —— ECE 从未测。
4. "class-balance KD 提升 3 点" —— 单 seed、缺 cbce、参照点低 1.5、与动机错位。
5. 任何跨机器汇总的均值（作者自己已禁止）。

### 现实的路线判断

这个仓库目前有两条互斥的路，而它现在**同时走在两条上**，这是最大的战略问题：

* **路线 A（负结果论文）**：标题类似 *When Privileged Knowledge Cannot Be Distilled*。需要的补充是：第二个数据集（DeLiVER）复现、ECE 补齐、一个"信息上界"实验。优点是与现有证据完全一致；缺点是需要新数据集，23 天很紧。
* **路线 B（正结果论文）**：需要 cbce 对照 + 3 seed + 一个**真正作用于夜间行人**的机制（特征级/区域级监督，而不是再调 logit 权重）。优点是有 CVPR 喜欢的涨点；缺点是现有证据一条都不支持它，等于从零开始。

我倾向 **A 为主、B 只做一个"最小可行"的子实验**：负结果 + 一个"如果把教师的热成像特征以某种形式给到学生、能否突破 48"的可行性探针。理由：A 的素材已经 80% 在仓库里，而 B 需要的机制连原型都没有。
